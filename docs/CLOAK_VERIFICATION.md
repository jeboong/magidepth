# MagiCloak 로컬 검증

2026-09-11, Windows / 독립 Python3.13.14 / OpenCV4.11.0 / NumPy2.2.6. 이 엔진의 프레임 연산과 YuNet은 CPU 경로이며 RTX GPU 성능 수치로 해석하지 않습니다. 원본은 `6f0e670f056c5ede87c0b0c390613ed6c499a455`입니다.

## 원본과 픽셀 일치

동일한 NumPy seed와 합성 입력으로 원본 체크아웃의 함수 및 이식 함수 출력을 직접 비교했습니다.

- A/B/C 각각96×128,41×57,8×8 ROI: uint8 출력 정확히 일치. A의 재사용 noise map도 정확히 일치.
- Grid: ellipse/rect, 회전−34°/0°/+26°, 비백색 BGR, margin, opacity, 교차점 dots를 포함한 출력 정확히 일치.
- 모든 A+B+C+grid 및 optical-flow temporal 경로의 연속5프레임 출력 정확히 일치.
- Tracker의 EMA/랜드마크/검출 놓침 동작 대조.

`python -m unittest discover -s backend/tests -p test_cloak.py -v`의 **22개 테스트가 모두 통과**했습니다. CI는 원본 저장소를 위 고정 revision으로 체크아웃한 뒤 픽셀 대조를 실행하도록 구성했습니다. 원본 체크아웃이 없는 로컬 환경에서만 선택적 원본 대조를 skip하며 나머지 계약/합성 출력/안전성 테스트는 실행합니다. FFmpeg/ffprobe가 없는 환경에서는 영상 인코딩 통합 테스트가 별도로 skip되므로 전체 검증에는 두 도구가 필요합니다.

## 순수 코어 속도 비교

960×540 RGB 합성 프레임, 결정론적 얼굴 박스1개, A+B+C+grid+tracking,20프레임씩9쌍을 번갈아 실행하고 첫쌍을 워밍업으로 제외했습니다. 검출·decode·encode·UI 시간은 포함하지 않습니다.

| 코어 | 8회 run의 프레임당 중앙값 |
| --- | ---: |
| 원본 FrameProcessor | 34.028 ms |
| MagiCloak 포트 | 34.204 ms |

포트/원본 비율1.0052, 약0.52% 차이로 이번 run 변동 범위 내였습니다. 알고리즘 가속을 새로 구현했다거나 모든 미디어에서 동일 FPS라는 주장이 아닙니다. 영상 길이·얼굴 크기/개수·CPU·프리셋에 따라 달라집니다.

## 실제 FFmpeg 및 검출기

- 앱의 FFmpeg8.1.2를 사용해 원본6개 품질 프리셋을 전부 실행했습니다.
- 320×180,24fps,0.5초 합성 영상+440Hz 오디오에 black/silent padding1초: 모든 출력24프레임,1.0초, 오디오 포함을 확인했습니다.
- 프리셋별 전체 처리 시간: visually_lossless0.530s / high0.178s / balanced0.180s / small0.166s / lossless0.178s / hevc_high0.249s. 작은 fixture의 단회 smoke이며 공정한 모델 속도 benchmark가 아닙니다.
- 기존 SeedanceCloak 캐시의 YuNet을 SHA-256 검증 후 실제 OpenCV FaceDetectorYN 추론에 사용했습니다. 합성 무얼굴 입력의 실행 성공 확인이며 얼굴 검출 정확도 평가가 아닙니다.
- 이미지/영상 혼합 배치, PNG alpha 보존, Unicode 경로, JPEG/WebP 저장, 출력 충돌 거부, 취소 시 원본 보존/임시 파일 정리를 테스트했습니다.
- 수동 grid/pad-only 경로는 YuNet을 초기화/다운로드하지 않습니다.
- 별도 `cloak_daemon.py` 프로세스의 JSON system/probe/preview 응답, 정확한 프레임 인덱스와 활성 렌더 중 취소 응답/정리를 실제 확인했습니다.

## 앞/뒤 패딩 추가 검증

- `pad_position` 생략 시 `after`, `before` 정상 수용, 그 외 값 거부를 확인했습니다.
- 12fps 6프레임 및 30000/1001fps 12프레임 합성 영상을 목표1초로 앞/뒤 패딩했습니다. 총 프레임 수뿐 아니라 디코딩한 **모든 프레임의 검은색/원본 순서**가 정확히 일치했습니다.
- 440Hz/880Hz 스테레오 원본을 사용해 두 채널의 무음 구간과 신호 구간을 PCM으로 디코딩하여 검사했습니다. 앞쪽 패딩은 `검은 프레임 수/FPS`만큼 두 채널을 함께 늦추며, 뒤쪽은 원본 오디오 시작을 유지합니다. AAC 경계 ringing 구간은 검사 창에서 제외했습니다.
- 목표보다 긴 영상과 패딩 OFF 영상은 앞/뒤 어느 선택에서도 프레임 수·원본 시작·오디오 시작이 유지되었습니다.
- 앞쪽 검은 프레임을 쓰는 도중 취소해 원본 보존, 미완료 출력 부재, 임시 파일/파이프 정리를 확인했습니다.

## 시스템 FFmpeg 재사용 교차 확인

독립 Python3.13.14에 시스템 FFmpeg/ffprobe **8.0.1-full_build**의 경로를 `FFMPEG_PATH`/`FFPROBE_PATH`로 명시해 전체 백엔드 **47개 테스트를 모두 통과**했습니다. 이는 계약·수학·모델 모킹·합성 미디어 통합 검사이며 실제 AI 모델 속도를 다시 측정한 결과는 아닙니다.

- MP4/MOV/MKV/M4V를 실제 저장·probe·decode했습니다. 12fps 및 30000/1001fps, 기존 스테레오 오디오, 앞쪽 패딩, H.264 QP0/YUV444 설정에서 모든 프레임의 원본/검은색 순서와 두 오디오 채널의 활성/무음 위치를 확인했습니다.
- 30000/1001fps 목표1초의 출력은 모두30프레임입니다. MP4/MOV/M4V의 container duration은1.001초, MKV는1.002초로1ms 차이가 있었으며 디코딩된 프레임 수와 패딩 경계는 같았습니다. 이는 목표 시간을 프레임 단위로 반올림하고 컨테이너가 시간을 표시하는 차이입니다.
- Windows에서는 취소된 인코더가 종료된 직후 임시 파일의 잠금이 잠깐 남을 수 있어 **해당 작업의 임시 파일만** 짧고 제한된 재시도로 정리합니다. 수정 후 앞쪽 패딩 중 취소를20회 반복해 전부 통과했습니다. 원본이나 이미 완료된 출력 파일은 삭제하지 않습니다.
- 새 Cloak 백엔드·테스트·문서에서 하드코딩된 개인 절대경로, 비공개 입력 파일명, 자격증명 패턴을 점검했으며 발견하지 못했습니다. 테스트 입력은 합성 미디어이며 개인 원본을 포함하지 않습니다.

선택적 상세 재현: `python backend/tests/test_cloak_smoke.py --output PRIVATE_SCRATCH_DIRECTORY`. 체크아웃과 생성 합성 미디어는 public source에서 제외합니다.

검증되지 않은 얼굴 인식 회피율·플랫폼 통과율·익명화 성공률은 제시하지 않습니다. 해당 목표가 필요하면 권한을 가진 별도 평가 데이터와 실제 대상 시스템에서 검증해야 합니다.
